# Story 5.3: Quick Speak with Voice & Emotion

**Status:** Complete
**Epic:** Epic 5: Quick Communication
**FRs Covered:** FR35

## Story Description

As a **MyVoice user**,
I want **Quick Speak to use my current voice and emotion settings**,
So that **preset phrases sound consistent with my TTS configuration**.

## Acceptance Criteria

### AC1: Current Voice Used
- **Given** the user has selected a voice profile
- **When** a Quick Speak phrase is triggered
- **Then** the phrase is generated with the currently selected voice

### AC2: Current Emotion Used
- **Given** the user has selected an emotion preset
- **When** a Quick Speak phrase is triggered (with BUNDLED or DESIGNED voice)
- **Then** the phrase is generated with the currently selected emotion

### AC3: Cloned Voice No Emotion
- **Given** the user has a cloned voice selected
- **When** a Quick Speak phrase is triggered
- **Then** the phrase is generated without emotion instruct
- **And** the TTS service uses neutral generation

### AC4: State Captured at Trigger Time
- **Given** voice and emotion can change at any time
- **When** a Quick Speak phrase is triggered
- **Then** the voice/emotion state is captured at that exact moment
- **And** subsequent changes don't affect the queued generation

### AC5: Same Error Handling
- **Given** Quick Speak triggers TTS generation
- **When** an error occurs (missing voice, TTS unavailable, etc.)
- **Then** the same error handling as normal generation is used
- **And** appropriate status messages are displayed

### AC6: Emotion Buttons Reflect Voice Type
- **Given** the user switches voice types
- **When** a cloned voice is selected
- **Then** emotion buttons are disabled
- **And** when a bundled/designed voice is selected, emotion buttons are enabled

## Implementation Details

### Voice Type Emotion Support

```python
# VoiceType enum property
@property
def supports_emotion(self) -> bool:
    """Check if this voice type supports emotion control."""
    return self in (VoiceType.BUNDLED, VoiceType.DESIGNED)
```

### TTS Generation Flow

In `app.py::_on_text_generate_requested`:
1. Get active voice profile from voice manager
2. Check if `voice_type.supports_emotion`
3. Only get emotion instruct if voice supports it
4. Create TTSRequest with or without instruct accordingly

### Integration Points

1. **EmotionButtonGroup**: `set_emotion_enabled()` called when voice changes
2. **App Controller**: Checks `voice_type.supports_emotion` before passing emotion
3. **Quick Speak Menu**: Uses same `text_generate_requested` signal path
