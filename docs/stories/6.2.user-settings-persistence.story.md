# Story 6.2: User Settings Persistence

**Status:** Complete
**Epic:** Epic 6: Settings & Configuration
**FRs Covered:** FR41

## Story Description

As a **MyVoice user**,
I want **my application settings to be automatically saved and restored**,
So that **I don't have to reconfigure the application every time I launch it**.

## Acceptance Criteria

### AC1: Settings Persist to Local Storage
- **Given** the user changes any setting
- **When** the setting is saved
- **Then** it is persisted to `%LOCALAPPDATA%/MyVoice/settings.json`
- **And** the file uses atomic writes to prevent corruption

### AC2: Persisted Settings List
- **Given** the following settings exist
- **When** the application saves settings
- **Then** these values are stored:
  - Monitor device (device_id, device_name, host_api)
  - Virtual microphone device (device_id, device_name, host_api)
  - Selected voice profile ID
  - Window position (x, y)
  - Window size (width, height)
  - Always on top preference
  - Window transparency level

### AC3: Settings Restored on Launch
- **Given** the user launches MyVoice
- **When** a valid settings file exists
- **Then** all persisted settings are restored
- **And** the window appears at saved position/size

### AC4: Emotion Defaults to Neutral
- **Given** the user launches MyVoice
- **When** the application initializes
- **Then** emotion is set to "Neutral" (not persisted)
- **And** this ensures consistent starting state

### AC5: Graceful Recovery from Corruption
- **Given** the settings file becomes corrupted
- **When** the application loads settings
- **Then** it falls back to default settings
- **And** the corrupted file is backed up for analysis
- **And** user is not blocked from using the application

### AC6: Missing File Creates Defaults
- **Given** no settings file exists (first launch)
- **When** the application starts
- **Then** default settings are created
- **And** a new settings file is generated

### AC7: Window Transparency Persistence
- **Given** the user sets window transparency
- **When** the transparency value is saved
- **Then** it persists as a float (0.0-1.0)
- **And** defaults to 1.0 (fully opaque) if invalid

## Implementation Details

### AppSettings Model Updates

Added `window_transparency` field to AppSettings:

```python
# UI settings
ui_theme: str = "dark"
always_on_top: bool = True
window_geometry: Optional[Dict[str, Any]] = None
window_transparency: float = 1.0  # Story 6.2: Window opacity (0.0-1.0, FR41)
```

### Validation Added

```python
# Validate window_transparency (Story 6.2: FR41)
if not isinstance(self.window_transparency, (int, float)):
    issues.append(ValidationIssue(
        field="window_transparency",
        message="Window transparency must be a number",
        code="INVALID_TYPE",
        severity=ValidationStatus.INVALID
    ))
elif self.window_transparency < 0.0 or self.window_transparency > 1.0:
    issues.append(ValidationIssue(
        field="window_transparency",
        message="Window transparency must be between 0.0 and 1.0",
        code="INVALID_TRANSPARENCY_RANGE",
        severity=ValidationStatus.INVALID
    ))
```

### ConfigurationManager Methods Added


### Architecture Decisions
- window_geometry stores position AND size in one dict (x, y, width, height)
- window_transparency uses float 0.0-1.0 (standard opacity range)
- Emotion NOT persisted to ensure consistent starting state
- Graceful degradation: corrupted file → backup → use defaults
- Auto-save enabled by default for seamless UX
