## Story

As a **MyVoice user generating TRUE_STREAM utterances on an Ampere-or-newer CUDA host**,
I want **the qwen-tts decoder + codebook predictor to run under `torch.compile` with `compile_mode="reduce-overhead"` (CUDA Graph replay) using the official upstream `Qwen3TTSModel.enable_streaming_optimizations(decode_window_frames=30, use_compile=True, compile_mode="reduce-overhead")` API, with a persistent compile cache at `%LOCALAPPDATA%/MyVoice/torch_compile_cache/` keyed on the seven dimensions that affect compiled-graph correctness, an "Preparing TTS engine…" indicator on cold compile that mirrors Story 17.2's "Preparing voice…" pattern, and a clean fallback chain to eager-mode generation if any compile / cache / capability stage fails**,
so that **first-chunk latency drops 1.5–3× on warm compile cache (per the upstream-blessed 2.15×-per-frame benchmark + the community-fork 5–10× TTFA evidence in `_bmad-output/planning-artifacts/research/technical-tts-streaming-fast-clone-research-2026-05-10.md`), the producer-bottleneck ratio Story 18.1 measured at 3.23× (reduced to 1.40 by Story 18.2's TF32+cuDNN engagement) closes to <1.0× sustained on RTX 5090, the bf16 path Story 18.3 shipped engaged-but-empirically-null finally pays for itself when composed with kernel-fusion and CUDA Graph replay (re-validating D-27's "bf16's tensor-core advantage may finally materialize once kernel-launch overhead collapses" hypothesis), the cold-compile UX is non-blocking (UI stays responsive; "Preparing TTS engine…" indicator visible per Story 17.2 inline-label precedent), and the joint NFR3 audition (≥3-listener blind A/B against the bf16+compile+pin-bumped output) certifies bf16-as-default + compile-as-default + pin-bump-to-`dffdeeq/Qwen3-TTS-streaming@3fdb4682` simultaneously, closing both Story 18.3's deferred audition and the D-22 Branch-B re-audition obligation in a single listener cycle**.

**`torch.compile` + CUDA Graph capture (PyTorch 2.10):**
- `compile_mode="reduce-overhead"` automatically captures CUDA graphs for repeated forward passes. Combined with a fixed `decode_window_frames=N`, this enables full graph replay without recompilation — the foundation of the multi-× speedups in the streaming forks.
- `dynamic=True` (the original epic-stub design) is **mutually exclusive** with CUDA Graph replay. The architecture rejects this option (D-21 sub-option (c)).
- First-call compile cost: 10–30s wall time per the research synthesis. Mitigated by D-23's background warmup + persistent compile cache (TORCHINDUCTOR_CACHE_DIR env var).
- Cache cold-vs-warm distinction: the inductor cache directory contains compiled-graph artifacts keyed on the exact graph shape + dtype + capability + torch version. The 7-dim `compile_cache.compute_key()` (architecture D-24) is the high-level cache key MyVoice maintains; the underlying inductor cache (managed by PyTorch) is mapped 1:1 to MyVoice's per-key directory via `set_torchinductor_cache_dir(key)`.
- VRAM impact: marginal for inference (no gradient-capture overhead). The compile cache itself lives on disk, not VRAM. Per-chunk forward passes hit the compiled graph in VRAM at runtime; the cold compile populates the disk cache so subsequent process launches reload from disk in ~1s rather than re-running the 10–30s compile.

**`AppSettings.tts_compile` semantics:**
- `"auto"` (default) defers to the hardware probe + compile-failure fallback: engages on Ampere+ CUDA when `enable_streaming_optimizations` is callable; falls through to eager on any failure. Mirrors `tts_precision = "auto"`'s discipline.
- `"on"` is user-explicit opt-in — engages on Ampere+ CUDA. Same hardware gate; CPU users still get eager mode (the hardware-emulation slowdown is a non-engagement reason).
- `"off"` is the NFR7 fallback path: forces eager-mode even on Ampere+. The user has observed a compile-related defect post-release (perceptual or correctness) and wants the lossless path. Mirrors `tts_precision = "fp32"`'s discipline.
- `"auto"` is the default because the joint audition (Task 9) is the certification surface — a passing audition means compile is safe-by-default on Ampere+.

**Persistent compile cache discipline (architecture D-24):**
- Cache key: 7 dimensions per AC #3. SHA-256 hex digest joined by `"|"`. Constructed in EXACTLY one place (`compile_cache.compute_key()`; P-10).
- Cache root: `%LOCALAPPDATA%/MyVoice/torch_compile_cache/` on Windows (mirrors V2 baseline's `%LOCALAPPDATA%/MyVoice/` storage discipline).
- Cache invalidation: any of seven dimension changes (qwen_tts_pin_hash bump, model_id change, precision_str toggle, torch_version upgrade, decode_window_frames re-tune, hardware tier change, compile_mode change) → cache miss → re-compile on next priming.
- No size cap in v1 (architecture D-24 explicit — "future enhancement if disk usage becomes a concern"). Each compile-cache entry is ~50-200 MB per the inductor cache pattern; expected steady-state size is single-digit GB across the lifetime of a torch upgrade cycle.
- Per-key directory pattern (`cache_dir_for_key(key)` returns `cache_root / key[:16]`) defends against directory collisions; full-key match in `meta.json` is the canonical "warm" signal.
